## THE MISSION

Create a fully integrated, downloadable, native macOS edition of Guilty Spark focused specifically on:

- Original Halo Mac Demo.
- Original Halo Mac Full/Retail.
- HaloMD and verified compatible legacy Mac content.

This is not a general Windows Halo editing-kit port.

This is the modern replacement for the original MacGamingMods workflow: everything that Eschaton, SwordEdit, SparkEdit and related classic Mac Halo utilities allowed creators to accomplish, combined into one modern interface with meaningful improvements.

The target user may already run the original 32-bit Halo game through an independent emulator or compatibility wrapper on Apple Silicon. A reported setup achieves approximately 27 FPS.

Spark itself must be a native 64-bit Mac application. It must not depend on that emulator to execute the editor.

The game-running compatibility layer is an optional, separately configured playtesting destination—not part of Spark's required runtime.

**The central requirement: a Mac user must be able to install Guilty Spark, open an original Halo Mac map, edit it, save/export a legitimate working map, and use it without installing Eschaton, SwordEdit, SparkEdit, Guerilla, Sapien, Windows Halo Tool or another specialist editor.**

## 2. COMPLETE ESCHATON-STYLE EDITING INSIDE SPARK

Study documented Eschaton behavior, supported versions and known limitations.

Implement its practical supported editing capabilities directly within Spark.

### Tag and metadata editing

Provide:

- Complete tag directory browsing.
- Tag searches, sorting, filtering and class identification.
- Typed field inspection and editing.
- Supported reflexives and nested structures.
- Flags, bitmasks, enums, strings and numeric values.
- Tag reference navigation and swapping.
- Dependency and reference-graph inspection.
- Hex/raw inspection for advanced users.
- Safe comparisons between maps and tags.
- Object duplication and supported tag cloning.
- Renaming supported tag paths and internal identifiers.
- Updating dependent references where the native format requires it.
- Clear validation of pointers, offsets, sizes, alignments and reflexive counts.

Support native Halo 1 tag classes according to their actual layout and edition-specific capabilities.

Do not invent tag fields or allow unsafe structural changes merely because the interface can display bytes.

### Extraction, injection and rebuilding

Implement supported Eschaton-style workflows:

- Extract individual tags.
- Extract related dependencies recursively.
- Export supported bitmaps, models, sounds and other resources.
- Import compatible replacement resources.
- Reinject supported native tag data.
- Replace references safely.
- Expand or reconstruct compiled caches when the operation is genuinely supported.
- Recalculate affected tables, pointers, offsets and resource boundaries.
- Validate resulting cache integrity.
- Independently reopen the output.
- Preserve original map hashes and maintain recoverable editing copies.

Distinguish safe in-place cache editing from operations that require complete structural rebuilding or missing authoring data.

Do not claim that every compiled map can be perfectly converted back into its original loose-tag source.

The objective is maximum genuine functionality, not dangerous unrestricted binary modification.

Provide an optional configuration flow:

**Connect existing Halo installation → Identify map directory → Inspect target compatibility → Export protected map copy → Optionally launch through the user's configured wrapper.**

An editor-only workflow must remain functional even if no game emulator is installed.

If supported game launching cannot be automated, give the user a clear manual playtesting path.
