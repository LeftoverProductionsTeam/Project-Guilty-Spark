### Mandatory extraction map creation workflow

**This is a required end-to-end feature, not a backend configuration screen.**

A creator must be able to launch Spark and complete the following through real mouse, keyboard and menu controls:

1. Choose **File → New → Extraction Map**, or convert a compatible existing map into an extraction project without altering its original source.
2. Select the target runtime and native map format.
3. Create or import the playable BSP environment.
4. Add and edit terrain, roads, caves, buildings, doors and other supported geometry.
5. Place player deployment points and define no-shield/plasma-pistol starting rules.
6. Configure the inventory system and starting equipment.
7. Place weapon, ammo, health, overshield and valuable-loot objects.
8. Configure loot tables, rarity, respawn and item persistence.
9. Place extraction zones, interaction points and inventory-banking behavior.
10. Place Covenant, Flood and supported bot/AI encounters.
11. Configure AI spawns, factions, difficulty, aggression, patrols and combat behavior.
12. Configure PvP, teams, friendly fire and player re-entry rules.
13. Configure dual wield, sprint and other supported mode-specific mechanics.
14. Configure persistent world, death, extraction, disconnect and restart rules.
15. Preview the environment, actors, inventory placements, triggers and extraction areas.
16. Save, Undo/Redo, close Spark, reopen the project and verify every authored setting persists.
17. Validate native tags, dependencies, scripts and runtime-specific configuration.
18. Compile an actual supported `.map` and any separately required game-mode/server package.
19. Independently read back the native output and verify its authored contents.
20. Launch the correct runtime directly from Spark.
21. Host a real extraction session and connect two actual game clients.
22. Verify real AI combat, PvP, looting, inventory banking, extraction and persistence.
23. Return to Spark, modify the map/game mode, rebuild or live-update through supported interfaces, and verify the resulting gameplay changes.

**No extraction creation workflow is accepted until the creator can perform and verify its actual supported operations.**

If an engine requires additional services or a supported extension for persistence and multiplayer rules, package and configure them explicitly. Never misrepresent a plain `.map` as supplying functionality that requires engine-side code.
