# PROJECT GUILTY SPARK — ONE HALO COMMUNITY

## THE COMMUNITY UNIFICATION INITIATIVE
### Create Together. Play Together. Keep Halo Alive.

**Mission:** Make Project Guilty Spark the central, open, welcoming entry point for Halo 1 creation, modding, collaboration, discovery, and multiplayer—without replacing, dividing, or locking out the existing community.

This initiative addresses a fundamental problem:

Halo has talented modders, powerful tools, custom maps, engine forks, dedicated servers, and active communities, but they operate through disconnected workflows.

Creators struggle to get their work into players' hands.

Players struggle to find compatible games, install maps, understand engine requirements, and discover new experiences.

Community projects compete for a relatively small player population.

**Guilty Spark must connect these worlds.**

Our product philosophy:

**One place to create. One place to discover. One place to find a game. Every compatible engine and creator welcome.**

# 1. UNDERSTAND THE COMMUNITY PROBLEM

Recent creator conversations identify several recurring challenges.

Treat these as individual developer experiences, not statistically proven community-wide opinions.

### Creator frustration

- Building a map can require many disconnected tools.
- Modern editing workflows remain difficult to learn.
- Creators have trouble packaging and distributing their content.
- Native asset and script dependencies are complicated.
- Existing tools sometimes solve only one stage of a project.
- Advanced features may require engine-specific source modifications.
- Some players want ambitious new experiences without knowing how to create them.

### Player frustration

- Custom maps are difficult to discover.
- Some servers have few human players.
- Bots may make servers appear more populated than they feel.
- Different engine versions cannot always join the same games.
- Missing maps, resources and protocol mismatches interrupt joining.
- Existing maps receive more playtime than new creations.
- Community events can be hard to discover.

### Community fragmentation

OpenCE, Chupathingy, MCC, Custom Edition and other forks have different priorities, release schedules, server infrastructure and capabilities.

Spark must remain neutral between their maintainers.

Do not incorporate unverified Discord accusations, interpersonal disputes or allegations into technical decision-making.

We want creators and players to choose Spark because it is useful—not because we try to replace their communities.

# 3. UNIFY THE SERVER BROWSER

Extend Spark's existing Multiplayer Hub into a real, useful directory of supported Halo 1 multiplayer sessions.

Integrate verified public discovery interfaces.

## Chupathingy Delta List

Official documentation:

https://halo.milenko.org/api

Live listing:

https://stats.chupathingy.org/v1/games

The public read-only API exposes information such as:

- Game/server name.
- Player count and capacity.
- Map name and format family.
- Gametype information when supplied.
- Network version.
- Protocol.
- Region.
- Host platform.
- Dedicated/player-hosted status.
- Public invite information.
- Password/locked state.
- Whether the server accepts new players.
- Listing freshness and verification state.

Respect its documented limit of 60 calls per minute per IP. Implement backend/native fetching, proper caching, backoff and stale-data handling.

Do not duplicate Delta's networking or host-management implementation.

## OpenCE

Investigate its documented server discovery and legitimate public listing interfaces.

Support joining available games using verified methods.

Never misrepresent OpenCE master-list approval as a requirement for all direct/LAN hosting.

## Halo Custom Edition

Use only supported public server-listing or discovery mechanisms.

Do not invent an API or attempt to impersonate a game client.

## MCC

Support legitimate MCC mod and multiplayer workflows.

Do not fabricate an MCC public-server discovery interface.

Do not claim MCC can connect directly to OpenCE or Chupathingy merely because a map loads in another engine.

### Browser acceptance

The Multiplayer Hub should display genuinely retrieved games from supported public sources.

Show the correct runtime icon, availability, map, mode and joining requirements.

A server may be visible without being joinable.

**Discovery is not cross-play.**

# 5. ONE-CLICK COMPATIBLE GAME JOINING

Use the existing Spark runtime adapter and source-identity architecture.

When a user chooses a server, Spark should determine:

1. The server's actual protocol.
2. Network version and compatible clients.
3. Required map family.
4. Required map checksum or version.
5. Required shared resources.
6. Which supported game clients are installed.
7. Whether joining is currently allowed.
8. Whether the selected client supports a documented external join mechanism.

Then perform the supported action.

For Chupathingy games, investigate and use its documented `halo://join/<invite>` mechanism when the actual installed client and operating system support it.

Do not silently register or hijack URI handlers belonging to another application.

For engines without supported direct joining, open the appropriate client and provide the join details.

### Clear outcomes

Show:

- Ready to Join.
- Missing Runtime.
- Incompatible Network Version.
- Missing Map.
- Wrong Map Version.
- Missing Resources.
- Server Full.
- Server Locked.
- Joining Unsupported.
- Experimental Compatibility.

Do not treat every Halo executable as interchangeable.

## CREATOR TO PLAYER — THE SPARK COMMUNITY BENCHMARK

### Creator side

1. Open Spark.
2. Build or modify a native Halo 1 map.
3. Preserve compatible source and dependencies.
4. Compile and test it.
5. Produce a properly attributed, native-compatible package.
6. Share it through an authorized destination.
7. Host or arrange a compatible multiplayer playtest.

### Player side

8. Open Spark.
9. Discover the test game or shared map.
10. Identify the required runtime.
11. Verify the map and resources.
12. Obtain permitted content.
13. Launch the compatible game client.
14. Join successfully.
15. Play with the creator.

### Feedback loop

16. Record a reproducible test result.
17. Return the creator to the original Spark source revision.
18. Make a correction.
19. Rebuild.
20. Play the updated version.

If the participating systems lack an API for one step, use an explicit guided workflow rather than inventing automation.

### Acceptance levels

- Native map created.
- Map compiled.
- Package validated.
- Map shared.
- Game discovered.
- Runtime compatible.
- Map available.
- Client connected.
- Two-player gameplay verified.
- Feedback returned to the creator.

A completed server browser does not mean the community loop is finished.

# FINAL PRODUCT DIRECTIVE

We are not building Guilty Spark to win an argument over which Halo tool or engine is best.

We are building it because Halo 1 has creators who want to make things and players who want new experiences—and too many obstacles between them.

A MacGamingMods veteran should be able to bring an old HaloMD project forward.

A traditional HEK user should be able to use their preferred native tools.

A Blender artist should be able to create an original world.

A Mantle user should be able to exchange supported map work with Spark.

An OpenCE player and a Chupathingy player should be able to find each other when their actual game versions are compatible.

An MCC creator should be able to build and share content for the real MCC runtime without proprietary conversion tricks.

A newcomer should be able to build their first native Halo map without memorizing twenty command-line tools.

And a creator should have a practical way to get real people playing their work.

**That's what bringing the community together means.**

Don't fragment the ecosystem further.

Don't force a new runtime, network, proprietary file format or account system.

Respect the tools, source formats, creators and players already here.

Connect them.
