## Save recovery contract and user actions

Before changing the descriptor, Save validates the history/snapshots, source/asset references, descriptor baseline, unique file identity and journal budget. The existing head records two hash-bound choices. A stop before descriptor publication selects the old acknowledged head; a stop after publication selects the new head. Incomplete temporary output is not acknowledged. A first Save whose index commit was interrupted is reindexed only when its descriptor and full bound history validate; unrelated/partial directories are retained.

Failed publication leaves current RAM edits dirty and preserves the earlier accepted descriptor/history. Native-owned source resources, imported assets and build receipts are preserved independently of older authored Undo snapshots. No optional recovery policy means unsaved RAM edits are lost on exit; the first-Save warning remains accurate. Existing journal64MiB/4096-file and RAM budgets remain; no old snapshots are automatically removed.

A real database-wait regression demonstrated that an external descriptor could change after initial admission but before publication. Save now carries the reviewed hash and unique file identity through the SQLite wait and managed writer. The independent writer's file stays intact, the database transaction rolls back, and local RAM remains unacknowledged. A duplicate clean-head receipt after Save is idempotent only after existing revision, reference, checksum and budget validation; genuine edits and stale callers retain their original rules.

A changed external descriptor or head is refused. Review the external `.gsproject` through the existing Import Project action to open a separate project identity; inspect its references before saving that reviewed copy. This leaves the old conflicting history and external author file intact. It does not silently merge either author's edits.
