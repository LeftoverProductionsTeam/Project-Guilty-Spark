# Native workbench integration and polish

This pass continues local master from the committed BSP Workshop and C39 foundation. It joins working systems; it does not replace the application or close unrelated runtime goals.

The newer [CE recovery and workflow follow-through](CE_SOURCE_RECOVERY.md) now adds reviewed corrected-source CE compilation, source-model stacking and Back/Forward navigation. Results below retain the earlier integration's exact measurements and negative evidence.

## What changed

- Workshop geometry and **Objects & gameplay** now use the same evaluated level surface. Geometry examples retain authored starts, placements, objectives and game mode. Custom models appear in the hierarchy. Their drawer has compact XYZ controls and rotation in degrees.
- Closed OBJ sources with complete UVs and explicitly assigned Halo shaders can become real static scenery, with model and collision tags, in a fresh native build. Both receive the same baked rotation/nonuniform scale. The original OBJ and authored project remain preserved.
- End snaps a selected custom model onto the evaluated Workshop floor; Undo/Redo, workspace switching and reopen retain the result. Material binding no longer briefly disables this command when geometry is unchanged. Non-colliding portal planes are excluded.
- Derived Workshop meshes are cached within two entries/16 MiB; scenario validation, source hashes and native build checks always run. Material-only changes reuse buffers while material validity is rechecked.
- Imported project descriptors reject UNC, device, mapped network and alternate-stream locations before referenced filesystem access. A failed import does not publish a blank project. Valid imports fork their own project and preserve supported authoring state rather than overwrite an existing project sharing the same map hash.
- OBJ materials/groups have explicit limits. Shared bitmap/sound path lookup is indexed once, while duplicate-path refusal, exact resource ranges and SHA checks remain intact. The playtest helper derives console scenario grammar from the verified document. Compiled output must retain its inspected hash through final validation.
- SparkLink guest identities are retained per verified TLS session. Legacy plaintext identities are ephemeral. Old project-wide records remain preserved but are ignored; they cannot silently migrate an old participant identity. A recovered instance of the same session can resume the same author with a new owner-supplied pinned invitation. The owner/local OS remains trusted.
- Choosing a classic CE/PC game folder fills the expected executable and data root before inspection/registration. Missing loose native template tags now report the exact missing tag and the next action.

## Use the connected source workflow

1. Open a source project in Level Editor; create/edit its rooms in BSP Workshop.
2. Switch to **Objects & gameplay**, import an OBJ using the existing asset import, and select it in the hierarchy.
3. Assign real source shader paths in Build tools, then match the OBJ materials in its custom-model drawer. UVs and a closed, consistently wound source are required.
4. Move/rotate/scale it; End drops to Workshop floor. Save, then choose **Build & check playtest** with matching native tools/tags.
5. Review the new build receipt and native logs. A validated cache is a compiler/readback result; actual game load and traversal are separate checks.

Current limits: 4096 triangles/65535 vertices per model, 128 placements, 64 distinct baked transforms and 32768 total source collision triangles. Transformed local bounds are limited to ±64 Halo units. This is static scenery; it does not turn OBJ files into animated bipeds, vehicles or arbitrary native shader systems. Custom model publication over SparkLink is not negotiated. Compiled-map preview additions retain their separate native extraction/build guard.
