In the memory-first application this is descriptor metadata referencing the original map in place. It does not duplicate the map or a tag SDK. Previously saved sources are not rewritten; ownership and authored-history guards protect unsaved independent work.

## User workflow under test

File → New → MegaWorld; select Timberland and Sidewinder from a connected owned CE installation. Construction → Plan adjacent terrain → Make three-route seam → Apply and Save. In Objects and Inspector edit an original player start, Undo/Redo and Save. Asset library → connected-runtime Timberland → Scenery → boulder_granite_small; drag the actual textured preview into the viewport. Inspector edits position and yaw/pitch/roll. Ctrl+C/V, one-action Undo/Redo and Save retain two distinct objects and one verified dependency closure. Fully close/reopen Spark, decode the referenced native model, build for Chupathingy, independently extract/read its standard scenario, then load the exact private CE cache in Chupathingy.

This is scenery authoring, not proof of arbitrary imported weapons, vehicles, AI encounters or scripted events in connected CE builds. Those gates remain distinct.
