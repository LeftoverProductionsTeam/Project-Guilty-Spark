# C42 — Find tools and default Halo materials

**Find tools** now shows compact installed-tool and download cards for the selected runtime, using the MCC editing kit already discovered through Steam when no explicit map/tool folder overrides it. Download links and setup actions sit on each card. They use the system browser and existing dependency guide; Spark does not pretend that every publisher has an automated installer.

Desktop application profiles can remember an explicitly selected Windows executable and launch it. Spark checks its PE architecture, full hash and path again each time; a changed or missing app requires a new selection. It launches without passing a map or tag path and records the observed process. This is separate from a verified map handoff. CLI tools keep their managed actions, and incompatible runtime profiles remain blocked. The existing native Baboon/Invader workflows retain their exact tool/source checks. A standalone launcher does not promote a research profile into a supported schema or native editor integration.

In the actual Windows app, an unconfigured MCC tool-folder setting now discovers the installed Guerilla. Find tools launched its responsive **HCE Guerilla** window, then a deliberately stale launcher hash was refused without starting another process. The installed executable remained unchanged. The selected-application registration was seeded in the isolated QA library for this test; the native file picker was not operated, and no publisher installer was run. The browser contract separately verifies Locate → explicit Launch, direct download links and retention of the edited map.

New QuickForge arenas receive original owned Halo metal and grass shader references before entering the editor. This preview preparation works without Invader or native extraction. The later native dependency preparation remains a separate build requirement. Existing untextured source shapes also receive defaults without waiting for unrelated library or build activity. Texture loading or missing owned resources stays visible.

Material source selection is now independent of the model/sound browsing source. Changing the sound library no longer clears the arena's surfaces. Both QuickForge and the four-view BSP Workshop use the same owned material reader. The native test created an arena through the actual UI with Invader unconfigured, displayed two native material previews, changed the sound browsing source and converted the existing geometry into Workshop; both views retained the textures.

MCC and CE use the owned source matching their requested preview target when available. OpenCE and Chupathingy can preview these editor defaults from an installed owned MCC/CE/PC source. The test found both exact shaders for all four runtime selections. These editor pixels do not establish a different runtime's compiler resources, conversion support or gameplay compatibility. If no owned compatible source exists, Spark explains what to link instead of inventing or bundling Halo textures.

The final executable also passed all 23 workspace routes and three concurrent pop-outs, and retained the working-directory-independent CE/OpenCE/Chupathingy discovery fix. [Exact metadata and limits](fixtures/c42-tools-defaults.json), [shared external editing](C42_SHARED_EXTERNAL_EDITING.md).
