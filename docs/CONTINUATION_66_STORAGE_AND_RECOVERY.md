## Containment, recovery and user controls

`storage.rs` persists shared reservations, OS-held leases, ownership markers, revision identity and actual allocation/fingerprints. `native_staging.rs` inventories before creating an output, refuses cyclic/source-contained copies and generated directories, streams 1 MiB copy buffers, verifies source/output hashes and adopts only complete tag files. A failed or killed operation never becomes an accepted build. Native compiler polling rejects a job when its owned reservation or disk safety reserve is exceeded; ordinary protected-phase cancellation behavior is retained.

Defaults for newly managed data: 24 GiB total, 16 GiB staging, 8 GiB per operation, 4 GiB free-space reserve, 256 MiB diagnostics. Preview/compiler categories are ledger categories, not universal enforcement over every legacy writer or Cargo. New diagnostic JSONL output is capped without truncating old logs. Different QA libraries within this repository share the same ledger.

Use **Settings → Storage & Cache** to inspect the ledger, change limits, adjust decoded preview memory / owned texture payloads / warm renderers, or request an itemized temporary-output review. Larger folder scans run only on request; they are serialized and informational. The first desktop attempt exposed a >120-second automatic scan; the corrected page became ready in **334 ms**. The later version with four-runtime discovery became ready in **1,929 ms**. These are individual native UI trials with different discovery work, not a general startup benchmark. No map textures, geometry or validation were omitted.
