**Checked:** 2026-10-26. **Baseline:** C21 exact cumulative source SHA-256 `da24087852919f99930ffbc31841f8088703a58b2a8477e4be52abdd12fe39c3`. Statements below compare C21/C22 source inspection with cited public Halo tooling documentation. A citation to a tool/engine project is not an assertion we have implemented or run it.

## Executive answer

The blocker is not a new button: it is the unproven end-to-end **original authoring → validated data → correct H1 `.tag` dependencies → compiled collision / portals / PVS → lightmaps → a loadable `.map` → all-five-mode scoring in the real game** loop. Current Spark offers multiple source-editor/preview/diagnostic segments but still lacks this acceptance gate. **Stop widening runtime promises until the baseline can genuinely build and play a small map.**

## High-value findings from online sources versus C21

1. **Bungie spawn recommendation:** archived Halo PC HEK guidance suggests at least **16 starting points per team** for multiplayer. C21's initial Guilty Spark Test Arena had four total, so its claimed test readiness was premature. The recommendation is an authoring guideline, NOT a universal engine crash threshold. C22 moves the original test preset to 16/team and creates a CTF-side source audit. Real Halo spawn behavior requires distance, geometry and enemy-pressure tests. https://nikon.bungie.org/misc/hek_tutorial/references/general/general_ld_info.html ; https://c20.reclaimers.net/h1/guides/multiplayer/player-spawns/
2. **Dangerous Tool cancellation:** Reclaimers explicitly says NEVER terminate `tool structure` mid-import: it can leave partial BSP tags and lose prior cluster/weather/sound palette data. C21 `Runner::run` killed ANY native phase after cancellation or 600 seconds, though only isolated jobs are used. C22 defers cancellation and soft timeout for `structure`, `scenario`, `lightmaps` until natural process exit, then stops later stages. This is intentionally not a hung-tool killer and requires owner Windows testing. https://c20.reclaimers.net/h1/h1-ek/h1-tool/
3. **True BSP is several interlocking systems:** `scenario_structure_bsp` is not merely a 3D mesh. Halo needs collision BSP, render lightmaps, portals/PVS, cluster sound/fog/weather/wind, optional fog planes (the `$` material symbol) and weather polyhedra. Do not call editable source tunnel joins compiled collision. https://c20.reclaimers.net/h1/tags/scenario_structure_bsp/
4. **Real lighting rebuild is a different process:** Halo Tool structure does not bake lightmaps. Lighting and sky/shader edits require rerunning radiosity; editor Three.js preview is not equivalent. https://c20.reclaimers.net/h1/tags/scenario_structure_bsp/lightmaps/ ; https://c20.reclaimers.net/h1/guides/levels/box-level/
5. **No magic lossless conversion:** extracted `.map` tags and original `.JMS`/`.tif`/`.hsc` sources are different. Reclaimer can extract models/textures from maps but not source tags, while MEK/Invader can extract/edit tags with their own compatibility constraints. Every import needs provenance and round-trip verification. https://c20.reclaimers.net/general/intro/ ; https://reclaimers.net/general/community-tools/reclaimer/ ; https://c20.reclaimers.net/h1/community-tools/mek/
6. **KOTH and CTF have actual game hazards:** two-marker hills can crash Standalone; a CTF start can be disabled if it lies nearer the enemy flag than its own. C21 already checks these as source signals but only in-game can prove scoring and spawn-clear behavior. https://c20.reclaimers.net/h1/engine/game-modes/
7. **Stock Halo CE multiplayer AI does not synchronize:** stock netcode lacks AI and most scripted-object sync. The CE community uses server/client script workarounds not applicable to MCC H1A; the desired six-person co-op and 128-player matches cannot be supplied by selecting the number in a game-mode editor. OpenCE claims co-op, 128 players and more as an evolving alternative engine: treat its GitHub roadmap/README as a project claim, not an independently validated shipped feature. https://c20.reclaimers.net/h1/guides/multiplayer/synchronization/ ; https://c20.reclaimers.net/h1/engine/netcode/ ; https://github.com/OpenCommunityEdition/OpenCE
8. **Different game engine build versions need separate output policies:** legacy HEK, MCC H1A, Demo/Mac/HaloMD, custom fork engines have different expectations. Do not transform a header and assume the cache is functionally compatible. https://c20.reclaimers.net/h1/h1-ek/ ; https://c20.reclaimers.net/general/intro/

## Suggested staged implementation order

- **C22 (this source patch):** 16-per-team Test Arena, Race vehicle markers, readable source spawn QA report, safe deferred native writer cancellation, research/acceptance ledger. No engine proofs invented.
- **First owner QA gate (before major scope):** Windows Rust/Tauri compile, fixture checksum, REAL Tool structure/semantic checks with legal owner tags, real lightmaps, running first complete map, one local + one second-client match. Capture exact app/engine/tool build IDs and logs.
- **Then:** import-to-source mesh fidelity, topological collision and portal authoring, complete shader/tag dependency graph, game-side Firefight/ZA and First Contact scenario scripts with AI pathfinding. Only once the engine gates pass expand to OpenCE/ChupathingyCE, historically accurate Mac/MacMD and VR/split-screen.

No third-party Halo binaries, maps, screenshots, copyrighted sounds/images, or archived tools were downloaded or redistributed for this audit. The 92 original requirement reconstruction and missing verbatim Phase 3–7 prompt caveat remain unchanged.
