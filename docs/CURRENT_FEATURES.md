# Current Spark capabilities

This is the C41 integrated Windows development workbench. Features below describe actual operations, with native compilation and gameplay kept separate. See the [consolidation report](FINAL_CONSOLIDATION_C41.md) for fresh verification and [398-row ledger](MASTER_FEATURE_LEDGER.csv) for the full requested scope.

## Maps and workflow

- Preserve original map/archive bytes and record exact identities, resources and provenance.
- Discover owned runtime maps and linked/downloaded assets; download supported HTTPS map/ZIP releases in Spark.
- Keep multiple maps open with independent cameras, workspaces, tags, histories and target settings. Pop out workspaces and Recording Director for multiple displays.
- Use Back/Forward to return to a workspace or Settings section. Keyboard undo/redo remains edit history, with a configurable default of 100 entries.
- Use one fullscreen mode, compact map/header controls, movable/resizable drawers, remembered layouts, searchable tools, onboarding, glossary and Academy guides.
- Choose Dark Glow colors, white-on-dark themes, whole-window transparency and tint.

## Level, geometry and asset editing

- Fly through actual source BSP/model geometry; select or marquee-select objects, drag the centered gizmo, type or scrub transforms, and edit source tags in a hideable drawer.
- Snap supported selected assets downward with End against verified level/model support, with grouped undo and changed-source refusal.
- Author QuickForge rooms, brushes, starts, objectives and supported native placements. Unconfigured surfaces automatically gain owned grass/metal preview shaders without compiler tools; preparing native imports and compiling still require matching tools and dependencies.
- Use four linked BSP Workshop views, topology/sub-element editing, extrusion, clipping, per-face UVs/materials, joined rooms, corridors and ramps.
- Assemble compatible source BSP sections with tunnels, generated collision and authored visibility portals. Compiler/clearance/PVS results do not certify a player walkthrough or independent BSP streaming.
- Preview actual models in the asset drawer. Supported drag imports extract recursive native tags into isolated staging, verify dependencies and compile through the matching source route.
- Import closed, material-assigned OBJ scenery through native model/collision compilation. Broader custom model classes and every runtime combination remain unaccepted.
- Audition supported source sounds before editor placement. Compiled sound emitters remain a separate goal.

## Tags, safe external tools and builds

- Browse collapsible tag classes, matching tags, typed fields and references. Root-object selection no longer interrupts dependency navigation.
- Use Smart Edit to review the saved revision and choose a verified route. Supported MCC Halo 1 cache-13 scalar fields and existing transforms can be saved as independent direct cache copies without extraction or a compiler.
- Direct writes bind exact IDs, paths, offsets and expected bytes; refuse unsupported structures; run the reviewed native CRC/info utilities; compare every unplanned byte and reopen native semantics. Other editions and structural edits retain independent gates.
- Extract/stage recursive tags, duplicate supported campaign dependencies into isolated source, and compile through matching tools. A compiled campaign revision still needs game-load acceptance.
- Hand off derived tags to configured Baboon, Guerilla/Sapien and compatible tools. Stable-save/content audits distinguish known writer associations, harmless normalization and invalid semantic edits.
- Preserve damaged candidates and original sources; accept/reconcile valid native edits as new revisions. Build accepted working tags without regenerating them from an older cache or geometry draft.
- Run source compatibility/dependency checks, isolated native jobs, source-bound receipts and output-integrity checks; inspect a compiled revision in a separate tab.
- Use supported MCC/CE source and conversion paths, Portability Lab and semantic comparisons. Universal any-map/any-runtime conversion is unfinished.

## Rendering and audio

- Share actual Halo materials across map, tag, asset and machinima previews: supported diffuse/detail/lightmaps, model reflections, transparent shaders, decals, sky and atmosphere.
- Recover original texture resources by exact identities. The Zombie Apocalypse reader supports 510 verified external images; unproven/non-flat cases remain reported rather than guessed. Standalone first-load acceptance renders 124 shader materials, including 75 from compatible installed MCC images, and 15 embedded lightmaps. Its original pack restores all 132 materials. Embedded pixels retain priority; compatible previews do not become compiler resources.
- Configure preview anti-aliasing and resolution scale. Complete engine shading, animation, reflections and lighting/fog baking are not accepted as parity.
- Find supported installed classic/MCC audio resources, decode verified supported samples, retain authored looping main tracks and rehearse spatial sound scenes.
- Keep per-map mute/volume, channel mix and linked intro/loop/end segments; include the saved sound scene in editor recording. CELT and complete game event/acoustic parity remain open.

## Collaboration and runtime controls

- SparkLink uses private invitation-pinned TLS, roles, authoritative ordering, acknowledged revisions, conflicts, participant-specific undo/redo, durable host recovery and frozen shared builds.
- The bounded native-content workflow is proven with three independent Windows processes and separate libraries: supported native pistol edit, validated scenery publication and placement, convergence, permission/refusal checks and native compilation. Each participant explicitly admits matching local source; peers cannot request tools or arbitrary raw patches.
- Existing-object MCC live controls include reviewed movement/scale readback, shared vehicle physics scaling, Shift sprint and editable first/third-person switching on the supported native profile. Historical owner observations remain distinguished from new gameplay tests.
- Smart Edit wraps explicitly bound temporary positions in expiring live plans and a local before/readback journal. It does not make persistent cache edits replicate to the game.
- Arbitrary spawning, live BSP replacement, cross-game protocol translation, general native uploads, remote tool execution and game-peer AI/editor replication are not provided by source synchronization.

## Machinima, gameplay authoring and Online

- Rehearse supported native biped/monitor animation, assign compatible Halo animation source families, compose shots, paths, tracking and lens settings.
- Use detached Recording Director for editor WebM/audio takes and explicit display/window capture. Script-based native camera/actor workflows are distinct from an independent MCC spectator adapter and OBS acceptance.
- Author mission beats, HaloScript, Firefight rules, encounters, custom power-up recipes, rotations and game-type plans. Simulations and generated scripts require native/game validation.
- Browse community listings and supported invitations with runtime-aware handoffs. MCC community-protocol bridging and expanded 8-player/128-player modes remain goals.
- Connect or optionally install checked Custom Edition into a separate managed location. Prepare private loopback dedicated servers from installed maps or validated project outputs, with exact matching-client copies, startup-file guidance and owned-process cleanup.
- Dedicated-engine map status and compiler/process tests pass. A genuine client join, visual first-run completion and Workshop collision walkthrough remain unverified.
