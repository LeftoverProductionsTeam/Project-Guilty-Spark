# Known limitations

C41 adds a reviewed Windows MCC 13 direct writer, not a generic cache relocator. Its explicit scalar/placement allowlist excludes legacy/extended/compressed caches, arbitrary references, new arrays/models, per-instance scale and BSP restructuring. Native source guards remain authoritative. The shared live planner reuses existing bound-object moves; fresh game acceptance, live spawning/BSP replacement and game peers remain open. Custom model/sound previews are not proof of native runtime import or full presentation parity. [Exact routes and tests](CONTINUATION_41_ENGINEERING.md).

C39 SparkLink now proves bounded native pistol-field editing, complete admitted scenery publication and placement across three real processes, with synchronization retained across workspaces. It does not share arbitrary native schemas or model/sound/animation uploads. Remote camera/work-area indicators, collaborative live runtime delivery and game-peer replication remain open. Eight configured slots are distinct from three tested participants on one physical machine. Host recovery uses a fresh invitation; automatic host election and offline multi-master merging are not implemented. [Native-content acceptance](C39_NATIVE_CONTENT_ACCEPTANCE.md), [setup](SPARKLINK_SETUP.md) and [security boundary](SPARKLINK_SECURITY.md).

C37 implements a Windows Baboon 0.3.2 / MCC H1 loose-tag handoff. Other upstream aliases are not complete Spark integrations. Live checks cover stable native headers, class/extension, payload CRC and bounded structure parsing with the reviewed Invader release. They do not certify every semantic relationship or invalid gameplay value. Unknown validator versions and unsupported/oversized input remain unverified. Some writers omit/rewrite checksums; unresolved cases require review. Filesystem events provide no writer PID: Spark shows known launch context and explicitly labels the actual writer unconfirmed. Structural conflicts and geometry reimports that would lose native source are blocked. [Evidence and recovery](CONTINUATION_37_ENGINEERING.md).

Current for the integrated C41 workbench; linked older observations remain historical. Inspection, native tag preservation, compilation, game loading, gameplay and peer agreement are separate evidence. Historical experiments remain in their linked reports; they are not current blanket support claims.

## Native formats and conversion

- Portability Lab checks existing runtime profiles and reviewed model, shader, resource, extension and script hazards. Complete field schemas, animation/skeleton rules, script-function auditing and every edition-specific limit are not implemented.
- Untouched-byte proof applies to the derived cache extraction input. A native no-op/edit test covers one canonical scenario, and exact loose-tag inventories cover native compiler input files. These are not universal lossless extraction/serialization guarantees.
- Imported-map conversion currently targets MCC through the existing Invader/H1A Tool path. Other target descriptors do not implement arbitrary converters. Xbox compressed-cache editing, unknown extensions and protected/corrupt layouts require dedicated verified adapters.
- Alpine CE-to-MCC compilation has real evidence and semantic reports. The explicit MCC UI profile omits CE menu dependencies; source sound distances may become explicit target values. Visual/audio, custom UI/HUD and retail MCC game acceptance remain separate.
- Native packages require matching official Excession metadata. A copied/compiled cache, corrected CRC or successful process exit does not establish package enumeration or game loading.

## Editing, rendering, sound and BSPs

- The shared renderer draws real BSP/model geometry, source materials, textures, lightmaps, decals and supported sky/fog. Full engine shader/animation/effect/water/weather parity is not established across all maps/runtimes.
- Compatible-runtime flat images are read-only previews, selected through exact unique bitmap paths and matching native image layouts. Embedded images and verified original resources take priority. Standalone Zombie Demo loads 124/132 shader materials from embedded/compatible MCC pixels; the remaining eight require its original pack. This does not reconstruct custom images, resolve missing original cubemaps, supply extraction resources or perform runtime conversion.
- Verified recursive scenery imports and closed material-assigned OBJ models have bounded native source compilation paths. Arbitrary classes, instance deletion/duplication/scale, unsupported source maps and actual game loading retain separate gates. Native tag duplication is not unrestricted compiled-cache array editing.
- MCC classic ADPCM sound banks and matching classic resources can auto-connect. CELT music/dialogue, native sound functions, alternate/detail/script events, occlusion/reverb and complete game acoustic parity remain open.
- The painted-detail gate covers Spark's BSP audio writer. It blocks changes involving detail payload when rounded inspection cannot certify preservation. Generic Sapien BSP resaves, exact detail-payload parsing and automatic repair/restoration are not thereby certified.
- The existing connected four-map world and prior collision/PVS/compiler results remain preserved. No new C36 four-map walkthrough, vehicle-clearance gameplay or 128-player acceptance is implied.
- Map histories retain 100 configurable in-memory undo steps by default; the complete undo stack does not survive restart. Project descriptors alone cannot recreate missing original assets.

## Runtime, networking and safety

- The experimental exact-build MCC adapter has bounded existing-object edits, coupled scaling and recovery checks. Arbitrary spawning/BSP replacement, game-peer edit/AI replication, engine-owned update boundaries and abnormal-exit recovery remain incomplete. Thread release checks do not promise zero crash risk.
- Community listings, invitation routing and private host preparation do not translate MCC's gameplay protocol. Protected Chupathingy invitations use that client's password prompt. Browser/native/community compatibility needs the exact upstream protocol/content, not just a matching legacy announcement number.
- Exact OpenCE/Chupathingy native private sessions ran over owned Xbox data, including asymmetric mixed-runtime behavior. Sampled position, phase and inventory differences remain explicit. Scripted impact-damage/death checks do not prove trigger input, projectile flight, full state parity, human play, two computers or AI agreement. Spark's listing-to-client flow remains a separate gate; see [the native record](C36_COMMUNITY_NATIVE_TESTS.md).
- Legacy Mac/PowerPC, Xbox-derived builds, Store/Proton and other Halo families retain separate profiles; detection is not editable/buildable/live/network support. The modern Windows editor is not a PowerPC G4 application. VR/OpenXR and native split-screen remain open.
- Original resources and SDK masters stay outside managed mutations. External tools are not OS-sandboxed. Atomic project files and SQLite are not one cross-resource transaction; interruption may require descriptor reimport. Windows development binaries are unsigned.

## Consolidated workflow note

Saved maps retain their source, tools and per-map view settings, but open map tabs are not automatically restored at application startup. Reopen the saved projects through the library. The consolidation acceptance explicitly follows that route; it does not claim session-tab restoration.
