# Architecture

C39 extends the existing shared source service with typed version-4 messages, invitation-pinned TLS, authenticated roles, durable authoritative transactions, scoped generated-structure leases and per-author inverse operations. An immutable local source admission adds one supported native field and bounded complete scenery publications. A session-bound frozen build is verified separately from the current draft. General native tag schemas and arbitrary binary imports remain outside this bounded document. [Native-content acceptance](C39_NATIVE_CONTENT_ACCEPTANCE.md), [SparkLink design](SPARKLINK_ARCHITECTURE.md), [private transport boundary](SPARKLINK_SECURITY.md) and [application/native file distinctions](PROJECT_FILES.md).

C38 uses a canonical tool capability catalog shared with the frontend. Managed Invader recipes operate on isolated candidates; the existing native parser verifies exposed fields and the existing complete-file transaction copier stages accepted/recovery revisions. Source publication compares the saved map, build and both native/Baboon selectors. Build startup, native acceptance and Baboon reconciliation share a source-operation guard. Native tags and compiler boundaries retain their formats. [C38 design and limits](CONTINUATION_38_ENGINEERING.md).

C37 adds an external-editor boundary in `baboon_native`, reusing the native watcher and working-tag compiler. Native tool code/schemas stay external. Accepted whole-file revisions are staged as fresh inputs below the validated parent job; source/SDK copies are never overwritten. Native header/class/payload-CRC checking is read-only, content-hash cached and separate from semantic parser/compiler proof. [C37 detail](CONTINUATION_37_ENGINEERING.md).

React 19 presents a central versioned Spark project. Tauri 2 commands bridge to Rust spark-core and the managed local library. SQLite stores library summaries/settings; project JSON stores edits, source identities, asset references and target configurations. Original maps are immutable managed copies.

C36 adds [native portability/preflight](NATIVE_PORTABILITY.md) through the existing runtime registry and build workflow. Reports and editor metadata stay outside native tags. Byte-preserving cache patches, exact loose-tag compiler inventories and audited semantic comparisons are distinct proofs; no new mandatory Halo format or game protocol is introduced.

- **Inspection/rendering:** bounded cache/header/tag readers → BSP/model streams and exact shader references → provenance-checked bitmap/DDS batches → Three.js materials. Generation-specific resource keys and spans must agree with pinned source/resource hashes. DDS pixels remain local, in memory; projects contain references.
- **Authoring:** World stages source-map transforms/fields. QuickForge maintains original source geometry and scenario metadata. Creator Studio and Firefight retain source-only semantics until engine bridges are verified.
- **Builds:** each managed job gets an isolated workspace and output folder. Explicit kit generation, target configuration, dependencies, tool identity, expected output/version/scenario and hashes gate acceptance. An exported JMS or successful process exit alone is not a playable map.
- **Recovery:** atomic project writes, versioned snapshots, bounded retention and source-bound restore previews. Source maps/assets are excluded from snapshot pruning.
- **Runtimes:** separate adapters and local registrations. Discovery, file checks, compiler checks, game tests and peer/network evidence are different records.
- **UI lifecycle:** QuickForge scene labels use WebGL sprites. They do not create independent DOM roots inside React's canvas container. A transparent frameless native window uses themed curved controls, native drag/resize/maximize, and guarded close/save.

See [C33 engineering](CONTINUATION_33_ENGINEERING.md), [runtime capabilities](RUNTIME_CAPABILITIES.md), [BSP pipeline](QUICKFORGE_BSP_PIPELINE.md) and [asset policy](ASSET_AND_COPYRIGHT_POLICY.md). The experimental exact-build MCC live adapter below is separate from the unimplemented game-peer AI/network translation paths.

- **Live adapter:** exact-build MCC Halo 1 process reads and bounded object-position writes use map/object identity and readback checks. No code injection or game-file writes. See [adapter limits](LIVE_ADAPTER.md).
- **Shared source:** SparkLink extends the private QuickForge service with bounded multi-editor TLS sessions, host revisions, disjoint field/axis rebasing, retained conflicting drafts and durable author history. Cameras stay local. Each editor's live-game adapter remains separate; source sync does not certify game replication.
